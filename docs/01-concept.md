# Концепция проекта

## Что это

**Quest Platform** — веб-платформа онлайн-расследований и интерактивных квестов.

Игроки покупают доступ к квесту, создают игровую комнату и приглашают друзей
по ссылке. Команда совместно проходит расследование в браузере в реальном времени:
исследует локации, находит улики, решает головоломки, ведёт общую доску,
общается в чате и голосом.

## Главный принцип

> **Код один. Квесты — данные.**

Движок универсален. Новый квест (дом, город, лес, поезд, бункер, цифровое
расследование) добавляется через админку как данные, без правки Java-кода.
Java-код меняется только при появлении действительно новой механики.

## Роли

| Роль | Возможности |
|---|---|
| `USER` | регистрация, покупка, создание сессии, игра, доска, чат |
| `ADMIN` | всё + создание кейсов, публикация, тест-режим |
| `AUTHOR` (позже) | создание своих кейсов |
| `TESTER` (позже) | прохождение DRAFT-кейсов |

## Аутентификация

- **Владелец сессии** — полноценный аккаунт (email + пароль).
- **Гости** — без регистрации. Заходят по ссылке `/join/{roomCode}`,
  вводят имя, выбирают аватар, получают `guest_token` в localStorage.
  Идентичность — только в рамках сессии.

Причина: трение убивает приглашения. Классический паттерн Jackbox / Skribbl.io.

## Модель покупки

```
USER → PAYMENT → ENTITLEMENT → CASE
```

Один платёж → один entitlement → N сессий (по правилам кейса).
`entitlement` — отдельная сущность от `session`. Сессия создаётся на основе
entitlement, но не связана с платежом напрямую.

## Game Session

`CASE` — сам квест.
`GAME_SESSION` — конкретное прохождение кейса командой.

У каждой сессии: свои игроки, прогресс, найденные улики, открытые локации,
решённые головоломки, заметки, гипотезы, история.

## MVP

1. Регистрация / логин.
2. Mock entitlement (без реальных платежей).
3. Создание игровой сессии.
4. Invite-ссылка `/join/{roomCode}`.
5. 2–4 игрока в комнате.
6. Выбор визуального аватара из пресетов.
7. Карта + локации.
8. Переход между локациями.
9. Интерактивные объекты.
10. Найденные улики.
11. Условия и события (исполняются движком).
12. Общий прогресс.
13. Заметки.
14. Базовая доска расследования.
15. Чат.
16. Realtime через WebSocket/STOMP.
17. Финал: вопрос → ответ → раскрытие.

## НЕ в MVP

- Голос (позже, LiveKit).
- Реальные платежи.
- Админ-билдер (сначала seed через Flyway).
- AI-диалоги.
- S3-загрузка медиа (сначала `/static`).
- Аналитика, отзывы, preview mode.
- Графовый редактор.

## Ограничения

- Публикованные кейсы **иммутабельны** (версионирование через `case_versions`).
- Прогресс — только на backend.
- WebSocket — не источник истины.
- Секреты — только через env.
- Модульный монолит, без микросервисов.
- Без Redis в MVP.
- Оплата одного игрока → entitlement → N сессий по правилам кейса.

## Принцип разработки

Каждый этап объясняется по схеме:
1. Что делаем.
2. Зачем.
3. Что должно получиться.
4. Какие файлы создаём/изменяем.
5. Код.
6. Разбор.
7. Как проверить.
8. Типичные ошибки.
9. Что дальше.

Не перескакивать. Не добавлять технологии «на всякий случай».
